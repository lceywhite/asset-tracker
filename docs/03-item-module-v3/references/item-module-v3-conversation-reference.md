后续工程阶段原文已单独续录至 [物品模块 v3 工程阶段对话续录](item-module-v3-engineering-conversation-continuation.md)，覆盖 Git 建仓、代码接入、界面反馈、Mac 交接和转入行程模块的过程。

## A. 产品与交付边界

1. 产品由 Codex 主导继续开发，但需要先梳理现有框架、工程和前期规划。
2. 阶段目标是单人 MVP，可通过 Xcode 直接安装到 iPhone 测试。
3. 最终同时支持手机端与网页端；Windows 开发期间需要网页预览和调试，之后将完整工程迁移到 Mac。
4. 保持“物品、行程、社区、我的”四个核心 Tab。
5. 底部中央加号是核心入口，必须保留，用于快速添加物品或行程。
6. “我的”合并用户与设置；社区保留入口但单人阶段不虚构内容、不上传本地数据。
7. 工程代码调整前先确认设计；本轮物品模块仅做设计、原型和文档。

## B. 物品添加与档案

1. 物品界面参考游戏物品档案的直观信息布局，但保持成熟工具应用的可填写性。
2. 添加流程同时保留快速添加和逐步添加；默认快速添加，页面内可切换。
3. 演示数据需要覆盖完整物品档案，以便确认最大信息量。
4. 添加页删除无实际作用的“在用、私人”。
5. 物品 ID 自动生成、唯一、不可编辑；详情中弱化显示。
6. 分类是电子设备、衣服、工具等标准属性类别；标签是自定义气泡。
7. 档案显示名称、ID、分类、标签、有效估值、购入价、购入时间。
8. 当前位置之后紧跟可折叠的位置历史。
9. “自由信息”统一更名为“备注”。
10. 产品属性、财务信息、维护属性默认折叠，只显示已填写内容。
11. 完整编辑展示全部字段和完整度；标准属性组内信息项可删可增。
12. 自定义属性组可改名、删除、新增多个，组内信息项同样可增删。
13. 估值偏好为不计算、手动估值、直线折旧；默认不计算。
14. 默认添加方式和估值规则后续进入“我的 → 偏好设置”。
15. 完整财务统计和折旧规则记入待办，本阶段不实现。

## C. 物品主页：被否决的第一方向

1. 初版尝试把“我的家、办公室、移动空间”作为平级顶层空间。
2. 用户指出主页应该先按使用场景分区，而不是把所有顶层空间平铺。
3. 因此初版主页原型只作为探索记录，不作为 v3 实现基线。

## D. 物品主页：确认的信息架构

1. 顶部为搜索框和“空间 / 物品”切换，默认空间视图。
2. 分区是主页组织层，不是实际位置层级。
3. 默认分区为我的包包、我的家、我的车库，均可改名。
4. 我的包包直接展示移动容器，例如通勤包、旅行箱、搬家打包箱。
5. 我的家展示房屋空间，向下包含玄关、卧室等区域，再包含衣柜、抽屉、行李箱、小推车等容器。
6. 我的车库展示车辆空间，向下包含乘员舱、后备箱等区域，再包含露营箱等容器。
7. 固定容器用于收纳归类；移动容器用于防丢、携带、搬家和经常核对。
8. 大型物品可直接属于空间或区域，不强制放入容器。
9. 新增分区和新增空间逻辑参考原版本。

## E. 空间卡片的最终规则

1. 每一级空间都可上传图片作为头像。
2. 首页卡片弱化显示空间价值与藏品价值。
3. 卡片不显示 L0、L1、L2，改为显示实际下级数量，例如“5 个区域”。
4. 有下级空间时预览几个下级空间，点击预览直接下钻。
5. 没有下级空间时直接预览其中的物品。
6. 点击卡片主体默认进入当前空间详情。
7. 取消“进入空间详情”“查看完整布局”等冗余文字按钮。

## F. 空间详情的最终规则

1. 包包、房屋、车辆、区域和容器统一进入空间详情，不再为包包单独直达核对页。
2. 顶部显示标题、下级空间数量、物品数量和藏品价值。
3. 空间详情不显示空间价值。
4. 添加按钮使用实际下级名称，例如添加区域、添加容器；同时保留添加物品。
5. 布局展示直接下级空间。
6. 多布局时标题后显示右箭头；单布局不显示。
7. 点击编辑后出现“＋”，可以新增布局。
8. 编辑状态支持拖动下级空间调整排版。
9. 物品清单只显示直属当前层级的物品。
10. 物品清单提供核对入口；点击物品进入物品档案。

## G. 分区管理的最终规则

1. 首页不单独显示改名按钮。
2. 桌面端可双击分区标题进入编辑。
3. 所有端可通过管理界面修改名称和说明。
4. 管理界面支持分区排序和新增分区。
5. 三个默认分区不可删除，自定义分区可以删除。
