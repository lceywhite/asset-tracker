# 物品守护版本管理规范

更新日期：2026-08-07
状态：行程模块 v3 正式基线确认后执行

## 1. 为什么物品和行程现在都是 v3

`物品模块 v3` 和 `行程模块 v3` 是两个模块各自的设计基线代次，不是整个 App 的版本。它们现在数字相同，但仍然独立管理。

- 物品模块经历了旧版结构、第一轮新版探索和最终确认的第三代档案/空间结构，因此定名为 v3；正式数据中的 `Item.modelVersion` 也已经升级到 3。
- 行程模块 v2 经过 11 轮原型细化并完成正式工程接入；随后在真实页面中统一完整周期、分段路线、连续弹窗携带清单、整包导入和自定义信息卡片，并由用户在 2026-08-07 明确确认新基线，因此升级为行程模块 v3。
- “行程 v2 原型第 11 版”仍是 v3 的历史设计来源，不改名为“v11”，也不等于当前产品版本。
- `Plan.modelVersion: 3` 是数据记录结构版本；它与“行程模块 v3”同为 3 只是巧合，不能互相替代。

## 2. 项目同时存在的五类版本

| 类型           | 当前值                       | 管理对象                     | 何时变化                             |
| -------------- | ---------------------------- | ---------------------------- | ------------------------------------ |
| App 发布版本   | `1.0.0-beta.1`               | 用户安装和发布的整个应用     | 形成新的可安装发布包并明确发布范围时 |
| 开发阶段       | Release 0 / Beta 1 / Beta 2  | 路线图与验收门               | 阶段退出条件完成时                   |
| 模块设计版本   | 物品 v3、行程 v3             | 单个业务模块的产品与信息架构 | 模块发生结构性重构并重新确认基线时   |
| 原型迭代版本   | 行程 v2 原型第 11 版（历史） | 同一模块基线内的界面修订     | 每一轮可辨认的产品反馈落地时         |
| 数据与备份版本 | IndexedDB v8、备份 v3        | 数据表、迁移和备份兼容       | 数据结构或迁移/兼容范围改变时        |

Git 分支、提交和标签是代码快照，不替代以上任何版本号。

以后在标题和文档中使用完整名称：

- `App 1.0.0-beta.1`
- `物品模块 v3`
- `行程模块 v3`
- `行程模块 v3 正式基线（2026-08-07）`

- `Plan modelVersion 3`

禁止只写“最新版”“v11”“最终版 2”等无法判断对象的名称。

## 5. 升级规则

### App 发布版本

遵循语义化版本：

- Major：不兼容的产品或数据边界变化；
- Minor：向后兼容的新功能模块；
- Patch：向后兼容的修复；
- `alpha` / `beta`：尚未达到正式发布门槛。

行程 v3 确认不自动修改 `package.json` 的 App 版本。只有形成新的完整测试包并确定发布范围后，才决定下一 App 版本。

### 模块设计版本

只有以下情况才升级模块版本：

1. 信息架构或核心流程重构；
2. 核心数据关系发生模块级变化；
3. 旧设计不再能作为实现依据；
4. 用户明确确认新基线。

普通文案、间距、卡片排序和单轮反馈只增加原型迭代号，不升级模块版本。

### 数据版本

- 记录结构使用实体自己的 `modelVersion`；
- IndexedDB 只有在表、索引或统一升级事务改变时才升版本；
- 备份格式只有在导出范围或兼容规则改变时才升版本；
- 每次升级必须同时提供旧数据迁移、旧备份恢复和自动化测试。

## 6. Git 管理规则

1. 一个明确模块阶段使用独立分支；当前行程 v3 阶段使用 `codex/trip-module-v3`。
2. 原型确认、数据层完成、界面接入完成分别形成可回滚提交。
3. 提交信息写清范围，例如 `feat: establish trip module v3 baseline`。
4. 只有阶段性验收通过后才打标签；标签描述代码快照，例如 `trip-v3-integration-baseline`，不替代 App 版本。
5. 每次提交前同步更新当前状态、实施记录和面向非技术人员的产品迭代日志。
