## 1. 产品定位

物品守护首先解决一个人的两类高频问题：东西平时放在哪里，以及出发和返程时有没有遗漏。产品采用本地优先设计；在真实账号、权限和同步服务完成前，不把演示能力包装成多人协作。

阶段目标：

1. 10 秒内记录物品及其房间、包和分类。
2. 5 秒内通过空间或搜索找到物品。
3. 为一次行程建立携带清单，独立完成出发和返程核对。
4. 数据可备份、可恢复，删除 App 前可以由用户主动带走。
5. 形成可由 Xcode 直接安装到 iPhone 的真实 App 工程。

## 2. 信息架构

正式导航固定为四个核心 Tab：

| Tab  | 当前职责                                           | 阶段边界                             |
| ---- | -------------------------------------------------- | ------------------------------------ |
| 物品 | 记录、查找、编辑物品；管理房间和包；快速添加       | 图片暂未升级为独立媒体仓储           |
| 行程 | 创建行程、选择携带物品、设置返程提醒、执行核对     | 暂无云端模板市场和跨设备提醒         |
| 社区 | 保留未来内容入口，说明计划与隐私边界               | 当前无假动态、假用户或假互动         |
| 我的 | 本地个人资料、统计、偏好、备份恢复、隐私、版本记录 | 设置与用户中心已合并，不代表在线账号 |

底部中央保留“+”快捷操作，位于“行程”和“社区”之间，可选择“添加物品”或“新建行程”。它是全局操作按钮，不是第五个内容 Tab，因此核心信息架构仍是四个 Tab。

## 3. 已实现的单人 MVP

### 数据模型

数据库当前为 v6。v5 将行程内容与核对结果拆开，v6 进一步接入物品模块 v3 的分区、空间树和布局：

```text
Item ── roomId / bagId
Plan（内部沿用 activities 表）
└── PlanEntry（嵌入 packingItems，拥有稳定 id）
CheckSession
└── results[entryId]（一次出发或返程的确认结果）
```

旧 v4 行程会自动迁移：清单条目补充稳定 ID，并移除旧 `checked` 字段。出发和返程会分别产生核对记录，刷新不会污染计划原文。

### iPhone App

已生成 `ios/App/App.xcodeproj`，最低系统为 iOS 15，竖屏运行，使用 Swift Package Manager 管理 Capacitor 插件。原生能力包括：

- 备份文件写入与 iOS 分享面板；
- 核对操作触觉反馈；
- 原生状态栏与启动屏；
- 相机用途说明和安全区适配；
- 网页资源随 App 打包，无网络也可打开核心功能。

## 5. Beta 2 真机验收清单

本阶段只在单人 MVP 功能完整、Windows 网页端全流程回归通过后启动；当前行程 v2 开发不执行 Xcode/iPhone 验收。

- Xcode 无错误解析 SPM 依赖，选择个人 Team 后成功安装。
- 冷启动进入“物品”，四个 Tab 可切换，安全区和键盘无遮挡。
- 新增带照片物品，退出并重启 App 后数据仍存在。
- 创建行程，完成出发核对；再次进入可看到已完成记录。
- 开始返程核对后中途退出，再进入可继续。
- “我的”修改昵称和默认视图后重启仍生效。
- 导出备份到“文件”，清空数据，再从文件恢复，实体数量和关联一致。
- 飞行模式下仍能使用物品、行程、我的和已打包的社区说明页。

## 6. 暂不开发

真实社区内容、家庭空间、邀请码、在线账户、云同步、QR 公开寻物和 AI 识图均不属于当前单人 MVP。它们需要服务端身份、权限、隐私、内容安全和冲突处理方案，不能只靠界面占位承诺。
