# 行程模块 v3 设计总说明

确认日期：2026-08-07
适用范围：当前正式 Web 页面与后续 iOS 单人 MVP 验收。

## 1. 产品定位

行程是一段会涉及物品携带、核对或位置变化的行动，覆盖通勤、日常外出、旅行、搬家和自定义类型。核心任务是建档、准备携带物品，并在出发、途中或结束时核对是否遗漏；攻略或花销等内容只作为用户自己维护的可选信息卡片。

## 2. 行程主页

- 顶部沿用物品模块 v3 的搜索框与加号语言；
- 当周七天日期轴常驻，有行程的日期只显示一个弱小圆点；
- 周标题右侧下箭头展开月历；月历用不同颜色的跨日标题条显示完整周期，同一行程跨越多天时保持连续；
- 日期下方只呈现行程时间线卡片，不单独设置“核对”首页分区；
- 卡片显示名称、类型、路线摘要、完整开始/结束时间、物品和移动容器数量；左侧用起止节点与虚线表达周期。

周轴负责快速判断“哪天有事”，月历负责看清“是什么事、持续多久”，避免同一信息在窄屏重复并造成拥挤。

## 3. 新建与编辑

- 基本信息：名称、类型；
- 行程信息：单程/往返、完整开始与结束时间、路线和出行方式；
- 单程包含一段去程；往返包含独立去程和返程；每段可填写起点、途经点、终点、出发/到达时间和交通方式；
- 携带物品摘要点击“添加物品”后打开清单弹窗；未完成正式建档字段时允许先保存草稿；
- 通用信息区容纳备注和可新增、编辑、排序、删除的时间线、分页、清单、键值、金额等信息卡片。

## 4. 携带物品清单

- 物品必须归入移动容器，不能以无容器的散件加入行程；
- 添加容器时先展示现有移动容器目录，选中后默认递归带入其中所有物品；导入结果保存为本次行程快照，容器以后变化时不会静默改写旧行程；
- 选择“新建移动容器”后才出现名称和分区字段，并同步加入物品空间；
- 每个容器内可从物品库搜索，或按空间结构逐级下钻；物品通过加号进入“本次添加”区，确认后一次加入目标容器；
- 清单支持全选/清除、星标双向切换、批量移动、二次确认移出、桌面拖动和移动端右滑；
- 容器提供明确的移除入口和二次确认，只从本次行程移除，不删除真实容器和物品档案。

## 5. 行程档案与核对

- 档案先显示基本行程信息和按移动容器分组的物品清单，再显示通用信息卡片；
- 每个阶段只显示一个主要核对动作：开始前为“出发核对”，行程中为“随时核对”，结束后为“结束核对”；
- 核对后在按钮附近显示当前完成进度；
- 结果支持待核对、已确认、未找到和跳过，可暂存、继续并只重核未完成项；
- 星标提醒规则在“我的－偏好设置”统一管理，当前仅保存规则，不虚构系统通知已发送。

## 6. 视觉与响应式规则

- 搜索、按钮、输入框、分段控件、卡片、圆角、边框和蓝灰色体系与物品模块 v3 一致；
- 390×844 为当前主要移动端 Web 验收尺寸；弹窗需要覆盖当前上下文并保持内部下钻，关闭后回到原填写位置；
- 页面不能出现横向溢出；长标题、路线和日期需要在窄屏保持可读。

## 7. 数据与版本边界

行程模块 v3 沿用已经完成迁移和验证的 `Plan.modelVersion: 3`、`CheckSession.modelVersion: 2`、IndexedDB v8 与备份格式 v3。本次升级是产品基线确认和界面信息层级收敛，不增加数据表、字段或迁移事务，也不改变 App `1.0.0-beta.1`。
