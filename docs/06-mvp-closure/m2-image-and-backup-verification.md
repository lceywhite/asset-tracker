# M2 图片与数据安全验收记录

验收日期：2026-08-07  
适用版本：App `1.0.0-beta.1`、IndexedDB v8、备份格式 v3

## 用户可以感知的变化

- 添加物品时，照片会在本机保存前自动缩小；每件物品最多 8 张，单张原图最多 25 MB，处理后最长边不超过 1600 像素、目标体积不超过约 1 MB。
- 空间头像同样自动优化，目标体积更小；表单会显示处理前后体积。
- 图片仍只保存在当前浏览器或 App 的本地数据库中，本轮没有接入云端图片服务。
- 本机容量不足时会明确提示减少图片，已有数据不会因为这次保存失败而被清空。
- 备份恢复失败会显示原因，不再表现为点击后没有结果。

## 破坏性恢复演练

在隔离的 390×844 浏览器环境中完成以下连续动作：

1. 从 IndexedDB v4 旧数据启动并自动升级到 v8；
2. 上传一张超过 1 MB、尺寸为 2400×1800 的测试照片；
3. 验证数据库中的图片最长边不超过 1600、体积不超过 1 MB；
4. 建立物品、空间位置、跨日行程、移动容器携带关系和核对记录；
5. 导出备份格式 v3；
6. 经过两次确认清空全部业务数据，并验证物品、空间、行程和核对记录均为 0；
7. 使用导出的文件执行“替换现有数据”；
8. 验证物品位置、行程携带物品、移动容器和核对记录的关联均恢复；
9. 分别导入损坏 JSON 和缺少 `items` 数据表的备份，验证界面给出明确错误且不进入恢复。

演练最终通过。过程中实际发现“备份预检通过但 IndexedDB 无法写入”的缺陷：备份对象被 Vue 深层代理后不再是 IndexedDB 可克隆数据。现已改用浅层引用保存导入载荷，完整恢复重新验证通过。
