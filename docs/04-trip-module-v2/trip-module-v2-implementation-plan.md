## 3. 目标数据模型

### Plan modelVersion 2

继续使用 `activities` 表，避免无必要地复制一套行程主表；记录升级为：

```text
Plan
├── id / title / type / status
├── tripMode: one_way | round_trip
├── departureAt / returnAt
├── origin / destination / transportMode
├── containerRefs[]
│   └── containerId / nameSnapshot / iconSnapshot / sortOrder
├── packingItems[]
│   └── id / itemId / containerId / nameSnapshot / categorySnapshot / starred / addedAt
├── notes
├── infoCards[]
├── modelVersion: 2
└── createdAt / updatedAt
```

规则：

- `packingItems.id` 是本次行程条目 ID，核对结果始终引用它；
- `itemId` 引用物品库中的稳定物品 ID，名称与分类快照用于物品被改名或删除后的历史阅读；
- `containerId` 必须引用移动容器；行程清单不允许出现无容器条目；
- 移动行程内分组不改变物品档案的真实位置；
- 从行程中删除只删除行程条目，不删除物品档案；
- 新建移动容器通过物品模块的空间服务完成，并同步进入物品空间。

### CheckSession modelVersion 2

```text
CheckSession
├── id / planId
├── kind: departure | anytime | end
├── status: in_progress | completed
├── results[packingEntryId]
│   └── state: pending | confirmed | missing | skipped
├── startedAt / completedAt / updatedAt
└── modelVersion: 2
```

旧布尔结果迁移规则：`checked: true` → `confirmed`；已操作但为 `false` → `missing`；没有 `checkedAt` → `pending`。旧 `return` 核对映射为 `end`，旧 `departure` 保持不变。

### 数据库与备份

- 预留 IndexedDB v7，为 `departureAt` 等查询索引和统一迁移提供升级事务；
- 旧 `startDate`、`endDate`、`startTime`、`endTime` 在迁移后保留兼容读取，不凭空补造缺失时间；
- 旧的无容器条目进入迁移待处理容器，不直接丢失；首次编辑时要求用户归入移动容器；
- 备份格式是否升级到 v4，取决于导出范围是否增加新存储；即使格式不升级，也必须验证 v1/v2/v3 旧备份恢复后的行程迁移；
- 所有迁移先写自动化测试，再修改正式升级逻辑。

## 4. 正式页面拆分

| 文件/组件                   | 职责                                                 |
| --------------------------- | ---------------------------------------------------- |
| `TripsView.vue`             | 搜索、当周日期轴、展开月历和行程时间轴卡片           |
| `TripEditorView.vue`        | 新建/编辑行程的基本信息、行程信息和通用信息          |
| `TripCarryListEditor.vue`   | 移动容器分组、星标、全选、批量移动和移出             |
| `TripItemLibraryPicker.vue` | 搜索、按空间下钻、购物车式本次添加                   |
| `TripDetailView.vue`        | 行程档案、容器清单、核对状态和通用信息卡片           |
| `TripCheckView.vue`         | 全屏逐项核对与结果处理                               |
| `tripModel.js`              | 默认值、规范化、阶段判断和兼容转换                   |
| `tripPreferencesService.js` | 星标提醒规则偏好；现阶段只保存和展示，不承诺系统通知 |

原有 `TripForm.vue` 在新编辑流程稳定后删除；不能一开始就删除，以便迁移期间保留可运行回退点。

## 5. 分阶段开发计划

### 阶段 0：版本与回滚基线

- 归档并确认行程 v2 原型第 11 版；
- 提交纯文档基线；
- 从当前物品 v3 代码建立 `codex/trip-module-v2` 分支；
- 记录迁移前数据库、备份和浏览器烟雾测试结果。

退出条件：任何后续代码都能回滚到物品 v3 已实现、行程 v2 尚未接入的状态。

### 阶段 1：领域模型、迁移与服务

- 新增 `tripModel.js` 与 v1 → v2 规范化；
- 扩展 `activityService`、`checkSessionService`；
- 增加稳定 `itemId`、`containerId`、星标和三态核对；
- 接入全局行程偏好；
- 完成旧数据库和旧备份自动化测试。

退出条件：不换界面也能安全创建、读取、更新和恢复 Plan v2。

### 阶段 2：主页时间轴

- 替换列表/月历抬头切换；
- 接入搜索、当周日期轴、弱下拉月历和行程卡片；
- 保留现有 `/plans` 路由和底部 Tab；
- 补充空状态、跨日行程和历史/未来排序测试。

退出条件：主页与确认原型一致，旧行程迁移后可正常显示。

### 阶段 3：新建、编辑与携带清单

- 接入统一行程档案编辑；
- 接入移动容器清单二级页；
- 接入物品库搜索/空间下钻和购物车式添加；
- 实现全选、清除、星标双向切换、拖拽移动、侧滑移出和二次确认；
- 新建容器复用物品模块 v3 的空间服务。

退出条件：在 Windows 网页端完整创建一个含多个容器和星标物品的行程，刷新后数据一致。

### 阶段 4：档案与阶段核对

- 重构行程详情；
- 根据当前时间与状态显示唯一核对按钮；
- 接入出发、随时、结束三种核对；
- 支持已确认、未找到、跳过和只复核未完成项；
- 核对完成后才显示状态进度。

退出条件：三种核对均可中途退出继续，完成记录独立保存，不修改原始携带清单。

### 阶段 5：通用信息与清理

- 接入备注；
- 接入独立信息卡片的读取结构，编辑能力按确认范围逐步开放；
- 删除旧重复提醒、重复类型和“组合为新包”等冗余逻辑；
- 删除不再使用的旧行程界面代码。

退出条件：正式路由中不再出现旧行程流程，历史数据仍可查看。

### 阶段 6：回归与交付

- 单元/集成测试、格式、构建；
- IndexedDB v6 → v7 与旧备份恢复测试；
- 390×844 网页核心流程烟雾测试；
- 行程与物品容器关系、备份/恢复、冷启动回归；
- 行程 v2 完成后先并入单人 MVP 的 Windows/Web 全流程回归；待整个 MVP 功能完整后，再统一执行 Xcode/iPhone 真机验收。

## 6. 本阶段不实现

- 外部攻略接入、在线地图、天气、预订和支付；
- 云端提醒、跨设备同步或多人共享；
- 自动重复行程和模板市场；
- 未经用户确认自动修改物品真实位置；
- 把星标偏好描述成已经接入系统推送。

## 7. 首批开发任务

代码开始后按以下顺序执行：

1. 为 Plan v2、CheckSession v2 和迁移写测试；
2. 实现领域规范化和服务层；
3. 更新备份兼容；
4. 接入主页；
5. 接入新建/编辑与携带清单；
6. 接入档案和核对；
7. 完成旧代码清理与浏览器回归。
