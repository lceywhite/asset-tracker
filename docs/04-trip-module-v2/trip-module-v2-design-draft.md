# 行程模块 v2 设计草案

更新日期：2026-08-07

状态：历史设计演进。当前正式实现已确认为行程模块 v3，以 [v3 设计总说明](../05-trip-module-v3/trip-module-v3-design-spec.md)为准。

第 4 版将“行程”定义为会涉及物品携带、核对或位置变化的行动，覆盖通勤、日常外出、旅行、搬家和自定义类型。旅行攻略仅作为用户自己维护的可选信息卡片。完整范围见 [行动档案设计](trip-module-v2-action-record-design.md)。

第 5 版继续收敛：首页日历改为时间轴内下拉；新建页取消核对设置，并按移动容器组织物品；行程档案只在当前阶段显示一个核对按钮，完成核对后才展示准备度。

第 6 版统一主页抬头与物品模块，恢复当周七天日期轴；核对结果进度与按钮合并；自定义信息卡片直接进入档案，并增加时间线、分页等预设格式，不再保留独立旅行扩展视图。

第 7 版移除新建页的重复和通用提醒规则，将提醒收敛为物品清单后的“重点关注”设置；行程中新增物品改到档案建立后；备注和自定义卡片合并进同一个通用信息区域。

第 8 版校正通用信息层级：“通用信息”只作为共同的大区域标题；备注、时间线和新增入口各自使用独立卡片，不再嵌套进同一个外层卡片。

第 9 版取消独立重点关注入口，把星标并入添加与管理物品流程；批量导入、移动和移出使用同一套批量选择；提醒改为全局偏好。通用信息卡片隐藏类型标签及多余说明。

第 10 版把携带清单拆成独立二级管理界面：物品只能归入移动容器，容器内再进入物品库搜索或按空间下钻选择；同时补齐侧滑删除、拖拽换容器和“标记 / 移动 / 删除”批量工具栏。

第 11 版继续简化操作文案与选择方式：新建页入口改为“添加物品”；清单页把添加移动容器移到末尾，并增加全选和清除；物品库改为购物车式“＋添加”，下方实时查看本次待加入物品。

2026-08-07 工程校正版不另增原型修订号：视觉统一为物品 v3 的蓝灰体系；单程和往返均使用完整开始/结束时间，往返拆分为独立去程与返程并支持途经点；添加物品先保存草稿；已有移动容器默认整包导入；自定义信息卡片进入正式编辑；跨日周期进入日历呈现。

2026-08-07 正式预览第二轮继续校正交互：跨日周期条改为不同颜色并显示档案标题；时间轴起止节点改为双色虚线；携带清单在行程页上方弹出，物品库在弹窗内继续下钻；添加容器先显示现有目录，选择新建后才出现字段；容器卡片补齐明确的移除操作。

最终确认：周日期轴不再显示周期条，只在有行程的日期显示圆点；彩色跨日标题条只保留在展开月历。该完整实现于 2026-08-07 确认为行程模块 v3。

## 1. 设计目标

行程模块围绕一个完整闭环设计：计划行程、按移动容器组织携带物品、按当前阶段核对、查看结果、保留行动档案。

本轮优先解决：

1. 用户进入首页后立即知道最近将发生哪些行程。
2. 新建行程时能快速复用容器和物品，但不改变物品的真实位置。
3. 建档流程保持简短，暂不要求用户配置核对规则。
4. 一个行程阶段只呈现一个明确的核对动作，核对后才生成准备度。
5. 通用资料和自定义扩展不打断行程信息与物品清单主流程。

## 2. 当前原型页面

### 已确认的视觉方向

- 采用方案 B“旅程时间轴”。
- 主色和控件统一沿用物品模块 v3 的蓝灰体系；原型中的暖白、墨绿、青绿仅作为历史设计记录，不再是正式工程规范。
- 行程主页通过日期标题和纵向时间轴组织近期行程。
- 其他页面延续物品 v3 的圆角卡片、蓝色主操作和灰色次操作，并保持克制的 iOS 工具风格。

### 行程主页

- 时间轴是唯一主页视图，不设置时间轴/日历抬头切换。
- 顶部使用与物品模块一致的搜索栏和新建加号。
- 搜索栏下默认显示当周七天日期轴。
- 周标题右侧显示弱下箭头，点击后在时间轴上方展开完整月历。
- 时间轴和“接下来”区域只显示行程卡片，不把核对记录拆成另一类主页事件。
- 行程卡片显示时间、名称、类型、路线、往返方式和移动容器数量。

### 新建行程

- 只保留一个建档表单，不区分快速和逐步创建。
- 基本信息填写名称和类型。
- 行程信息填写单程/往返及完整开始/结束时间；路线按去程和可选返程分别填写起终点、途经点、分段时间和出行方式。
- 携带清单以移动容器为单位组织，新建页只展示摘要和“添加物品”入口。
- 二级清单页可选择已有移动容器或新建移动容器；已有容器默认递归带入全部物品并保存本次快照，物品不能脱离容器单独加入。
- 已有容器优先排列，“添加移动容器”固定放在所有容器之后；容器列表上方提供全选和清除。
- 每个容器各自提供“从物品库添加”，支持搜索以及按物品空间布局逐级下钻。
- 物品库不使用勾选框；点击右侧加号加入“本次添加”，用户可在页面下方核对或移除后再一次提交。
- 新建页不显示“行程中新增物品”，该入口仅在档案建立后提供。
- 清单页显示当前星标提醒规则和设置入口；单件物品可直接打星。
- 物品行支持勾选、侧滑删除和拖拽到其他容器；勾选后的批量操作收敛为标记、移动、删除，标记按钮可再次点击清除标记。
- 单件和批量删除均需二次确认，只移出本次行程，不删除物品库档案或改变真实位置。
- 普通物品仍参与核对；星标物品默认在出发和结束前一天晚上提醒。
- 提醒时间不在行程中逐次配置，统一在“设置－偏好设置”中调整或关闭。
- 删除重复和通用提前提醒规则；新建页的通用信息只保留备注。

### 行程详情

- 顶部只展示名称、类型、时间、路线、出行方式和行程时长。
- 携带清单紧随基本行程信息，并按移动容器分组。
- 档案建立后可统一添加、星标、批量移动或移出已有物品；新增正式物品仍使用独立入口并同步物品库。
- 物品清单之后只显示一个核对按钮：开始前为“出发核对”，进行中为“随时核对”，结束后为“结束核对”。
- 核对状态进度与按钮放在同一张操作卡片中；未完成核对前只显示按钮，完成后在按钮上方显示已确认和未找到情况。
- 核对之后只保留一个“通用信息”大区域；备注、自定义时间线和其他卡片作为同级的独立卡片连续排列。
- 自定义信息卡片参考物品档案属性组，支持自定义标题与信息项，并预设键值、时间线 / 分页、清单和金额统计格式。
- 档案阅读界面不显示“多行文本”“时间线 / 分页”等卡片类型，也不展示“可改标题或删除”等操作说明；需要编辑时再进入卡片编辑界面。
- 每日安排使用分页切换日期，在每一页内按时间线展示记录。
- 暂不保留单独的旅行扩展页面；更完整的卡片配置方式留待后续设计。

### 全屏核对与结果

- 单项核对提供“未找到、跳过、已确认”三个结果。
- 支持返回上一项，并保存中途进度。
- 完成后显示三类结果统计和需要继续处理的物品。
- 可以只重新核对未完成项目。
- 返回档案后，根据本次结果展示准备度，不提前计算虚假状态。

## 3. 演示数据覆盖

原型以“工作日通勤”为主档案，同时展示旅行和搬家：

- 通勤档案包含 2 个移动容器、9 项正式物品；
- 新建页演示添加移动容器，并在目标容器内从物品库搜索或按空间下钻选择；
- 已确认、未找到和跳过三种核对结果；
- 首页同时展示通勤、旅行和搬家行程；
- 旅行示例只通过可选扩展卡片记录个人攻略、具体规划和花销。

## 4. 工程接入阶段继续验证的细节

1. 原型保留“未找到”和“跳过”两个独立核对结果；工程实现需要验证用户是否能稳定理解差异。
2. 结束核对第一阶段默认覆盖全部携带物品，后续再评估是否增加“只核对需带回物品”。
3. 高频行程复用不进入本轮核心接入，复制、常用行程或自动重复另行设计。
4. 扩展信息卡片已支持预设类型、新增、编辑、排序和删除；后续再优化大量卡片折叠与复杂字段配置。

## 5. 当前不进入工程的内容

- 不修改 `activities`、`packingItems` 或 `checkSessions`。
- 不升级数据库版本。
- 不接入系统日历、定位、推送通知或云同步。
- 不开发多人共享或社区模板市场。
- Mac/Xcode 真机验收继续作为延期项目保留。
