# 已否决方案：完整旅行档案设计

更新日期：2026-07-28

状态：已于 2026-07-28 否决。否决原因：错误地把“行程”收窄为旅行规划，并将外部攻略接入置于核心流程；仅作为决策历史保留。

## 1. 产品定位

行程模块不再只是“给物品建立一个核对清单”，而是一个本地优先的个人旅行档案：

> 把攻略灵感、每日路线、交通住宿、预订凭证、预算、待办、携带物品和出发/返程核对放在同一个行程里。

当前阶段不建设在线订票交易、自动代下单、多人实时协作或公开攻略社区。外部攻略、预订和地点信息首先作为用户自己的资料接入，保留来源并允许手动修订。

## 3. 新版信息架构

### 行程主页

- 日期条与纵向时间轴仍是主结构。
- 行程卡片同时显示日程天数、预订资料数和准备进度。
- 保留新建、复制上次和使用模板。

### 新建行程

默认进入快速创建，也可切换逐步创建。

四种起点：

1. 自己规划；
2. 导入攻略链接、截图、长文本或文件；
3. 使用模板；
4. 复制历史行程。

快速创建一页覆盖：

- 名称、出发地、目的地、日期；
- 同行类型、人数、节奏、兴趣、交通偏好、预算和住宿区域；
- 每日日程、地点地图、交通住宿、预订凭证、攻略、预算、准备清单六类档案能力；
- 首批车票、酒店或攻略资料；
- 物品库、移动容器、临时清单和返程核对规则；
- 特殊需求与备注。

逐步创建调整为五步：

1. 创建方式；
2. 基本信息与偏好；
3. 日程、攻略和预订资料；
4. 物品、待办与核对；
5. 确认。

### 行程详情

详情页分为四个主要分区：

| 分区 | 解决的问题               | 主要内容                                               |
| ---- | ------------------------ | ------------------------------------------------------ |
| 总览 | 现在最需要处理什么       | 行程阶段、天气、提醒、最近安排、准备度、预算           |
| 日程 | 每天什么时候去哪里       | 日期、地图路线、交通时间、地点、餐饮、住宿、预约       |
| 攻略 | 为什么去、去前要知道什么 | 攻略来源、提取结果、景点美食、交通提示、避坑、离线资料 |
| 准备 | 出发和返程是否遗漏       | 待办、移动容器、正式物品、临时项、出发/返程核对        |

### 每日日程

每个日程条目可以是：

- 地点/景点；
- 餐厅；
- 航班、列车、公共交通、自驾路段；
- 酒店入住/退房；
- 门票、演出或预约；
- 自由活动；
- 普通备忘。

每条记录可填写开始时间、预计时长、地址、交通方式、费用、确认号、附件、备注和攻略来源。

### 攻略与资料

资料接入流程：

```text
链接 / 图片 / 长文本 / 文件
        ↓
保留原始来源
        ↓
提取地点、时间、费用、营业时间和提示
        ↓
用户筛选与修订
        ↓
加入某一天的日程或保存为行程资料
```

攻略内容按景点、美食、交通、住宿、购物、避坑、天气穿着、紧急信息分类。原始来源与整理后的个人笔记同时保留，避免自动整理覆盖用户资料。

## 4. 与物品模块的关系

- `packingItems` 继续使用稳定条目 ID。
- 正式物品条目应保存 `itemId`，不能只靠名称关联。
- 按移动容器批量加入时，只创建本次行程分组，不移动物品档案的真实位置。
- 临时清单用于票据、零食、一次性用品等非资产内容。
- 出发和返程继续生成独立 `checkSessions`。
- 返程默认覆盖正式物品；消耗品、赠送物品和明确排除项不进入返程核对。
- 当前正式代码中的“行程内组合为新包并移动真实物品位置”需要在后续实现阶段删除。

## 5. 后续数据模型预留

正式开发前单独评审数据库迁移。设计层建议将一份行程拆为：

```text
Trip / activities
├── tripDays
├── tripEvents
├── tripPlaces
├── tripSources
├── tripReservations
├── tripExpenses
├── tripAttachments
├── packingItems
└── checkSessions
```

其中 `activities` 可以继续保留为行程主表名称，以降低旧数据迁移风险；新增明细应使用稳定 ID，不把全部复杂资料继续塞进一个不可维护的大对象。

## 6. 分阶段实现建议

### 第一阶段：本地完整档案

- 手动创建每日安排、地点、预订、费用和攻略笔记；
- 保存链接、图片、文件和原始文本；
- 与现有物品和核对流程打通；
- 所有内容进入备份。

### 第二阶段：资料识别与辅助整理

- 从图片、文本和支持的链接提取候选信息；
- 用户确认后才写入正式日程；
- 路线顺序、交通时间、天气和营业时间作为可刷新信息。

### 第三阶段：联网增强

- 地图、实时交通、天气、航班/列车状态；
- 更丰富的目的地资料；
- 是否接入 AI 规划、邮箱预订识别或社区攻略，需要单独评估隐私、成本和服务端能力。

## 7. 本轮待确认

1. 行程详情采用“总览、日程、攻略、准备”四分区是否合适。
2. 新建行程的四种起点是否完整。
3. 攻略资料是否同时保留原始内容和整理结果。
4. 预算是否先做总预算与分类支出，不做多人分账。
5. 第一阶段是否以本地手动录入和附件保存为准，将自动解析放到第二阶段。
