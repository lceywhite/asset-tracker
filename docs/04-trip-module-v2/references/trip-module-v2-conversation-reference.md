## A. 最终确认的模块定位

1. 行程是会涉及物品携带、核对或位置变化的行动档案，不等同于旅行。
2. 通勤、日常外出、旅行、搬家和自定义行动共用一套核心流程。
3. 旅行攻略只允许作为用户自己维护的可选信息卡片，不接入外部攻略，不占据核心流程。
4. 核心闭环是建立行程、组织移动容器和物品、出发/随时/结束核对、保留核对结果。
5. 设计保持物品模块 v3 的成熟、克制移动端视觉语言。

## B. 最终确认的主页与档案

1. 主页顶部为搜索栏和加号，下方保留当周七天日期轴。
2. 完整月历通过弱下箭头在时间轴内展开，不设置列表/日历抬头切换。
3. 主页只显示行程卡片，不把核对记录拆成独立事件。
4. 新建使用一个统一档案表单，填写名称、类型、单双程、出发/返程时间、起止地点和出行方式。
5. 行程详情优先显示基本行程信息、按移动容器组织的物品清单和当前阶段唯一核对按钮。
6. 核对完成后才显示物品核对状态进度。
7. 备注、时间线和其他自定义信息卡片属于同一个“通用信息”区域，但各自保持独立卡片。

## C. 最终确认的携带物品流程

1. 新建和详情中的入口统一叫“添加物品”。
2. 携带清单是二级界面，物品必须归入移动容器，不能散落在容器外。
3. 可选择已有移动容器，也可新建并同步保存到物品空间。
4. 每个容器内进入物品库；物品库支持搜索和按空间布局逐级下钻。
5. 物品库采用购物车式“＋添加”，页面下方显示“本次添加”并支持逐项移除。
6. 清单顶部提供全选和清除；勾选后提供标记/清除标记、移动和删除。
7. 单件删除和批量删除均需二次确认，只移出本次行程，不删除物品档案或改变真实位置。
8. 星标提醒规则默认是出发和结束前一天晚上，设置入口放在偏好设置；当前阶段不代表系统通知已经接入。

## D. 被否决或移除的方向

- 把行程收窄为旅行规划并接入外部攻略；
- 首页以核对事件为另一类时间轴内容；
- 快速/逐步两套行程创建流程；
- 在新建行程中混入“行程中新增正式物品”；
- 每个行程重复配置通用提醒和逐项提醒；
- 独立“重点关注设置”页面；
- 把备注、时间线和新增卡片嵌进同一张外层卡片；
- 允许无移动容器的散装物品进入行程。
