# 行程模块 v2：行动档案设计

更新日期：2026-08-07

状态：历史设计文件。行程模块 v2 原型第 11 版和工程校正已成为 v3 的设计来源；当前正式基线见 [行程模块 v3 设计总说明](../05-trip-module-v3/trip-module-v3-design-spec.md)。

## 1. 产品定位

“行程”是一次会涉及物品携带、检查或位置变化的行动，不等同于旅行。

核心目标：

1. 记录日常或一次性行动；
2. 出发前明确需要携带什么；
3. 途中、结束或任何需要的时候检查是否遗漏；
4. 搬家等行动结束后，清楚哪些物品真正改变了位置；
5. 旅行规划、花销等内容作为可选扩展，不干扰所有类型共用的主流程。

核心闭环：

```text
建立行动档案
→ 确定携带物品
→ 出发核对
→ 随时检查
→ 结束/返程核对
→ 必要时确认物品位置变化
```

## 2. 行程类型

| 类型     | 典型场景               | 重点                                   |
| -------- | ---------------------- | -------------------------------------- |
| 通勤     | 上下班、上学、固定路线 | 重点物品、去程与返程检查               |
| 日常外出 | 健身、购物、办事、探亲 | 快速建立一次性携带清单                 |
| 旅行     | 周末游、长途旅行、出差 | 往返核对；可选攻略、分段计划和花销卡片 |
| 搬家     | 整体搬迁、分批搬运     | 批次清单、起止位置、结束后确认新位置   |
| 自定义   | 用户自行命名           | 使用通用行程字段与核对流程             |

类型用于提供默认值，不应锁死字段。用户可新增自定义类型。

## 3. 行程主页

主页以时间轴为唯一视图：

- 顶部与物品模块保持一致，使用搜索栏和新建加号；
- 时间轴按实际日期和时间呈现行动；
- 默认保留当周七天日期轴，点击日期查看当天记录；
- 周标题右侧使用弱显示下箭头，点击后在原位置展开完整月历；
- 周日期轴只用圆点标记当天有行程；下拉月历用连续色条覆盖完整日期周期，不同档案使用不同颜色，色条内直接显示行程标题；
- 常用行程的复用方式后续单独设计，主页本轮只展示真实建立的行程档案；
- 主页只显示行程卡片，不把某次核对拆成独立时间轴事件；
- 行程卡片呈现类型、开始与结束时间、起止地点、出行方式和移动容器数量；同一行动只显示一张卡片，不在结束日重复生成记录；卡片左侧的起止时间使用留有呼吸间距的节点和双色虚线连接，不让竖线紧贴时间文字。

示例数据应同时包含工作日通勤、周末旅行和搬家，避免再次把模块表现成旅行专区。

## 4. 新建行程

不再区分快速创建和逐步创建，使用一个清晰的行程档案表单。

### 基本信息

- 名称；
- 类型：通勤、旅行、搬家、自定义；
- 自定义类型名称。

### 行程信息

- 所有行程都必须有完整开始时间和结束时间；“单程”只表示路线方向，不表示没有结束；
- 单程包含一段去程，可填写起点、途经点、终点、出发时间、可选到达时间和出行方式；
- 往返包含去程和返程两段，返程独立填写起点、途经点、终点、出发时间、可选到达时间和出行方式；
- 行程结束时间描述整个行动档案的结束边界，返程出发/到达时间描述具体返程路线，二者不混为同一个字段；
- 途经点可按路线顺序增加、修改、删除和排序；
- 出行方式：步行、骑行、公共交通、驾车、火车/飞机、搬运车辆或自定义。

### 携带物品清单

- 新建页只显示移动容器摘要，点击“添加物品”在当前行程上方打开二级弹窗；
- 从容器继续添加物品时，在同一个弹窗内顺延进入物品库，返回后仍停留在本次携带清单，不额外堆叠整页路由；
- 清单必须以移动容器为单位，不能把物品脱离容器单独加入行程；
- 添加容器时先直接展示物品空间中的现有移动容器目录和“新建移动容器”选项；只有选择新建后才展示名称和保存分区字段；
- 选择已有容器时默认递归带入它当前包含的全部物品；新建容器同步保存到物品空间；
- 整包导入保存的是本次行程快照，之后容器内容变化不会暗中改变既有行程；用户可主动点击“检查更新”重新同步；
- 每个容器各自提供“从物品库添加”，先确定目标容器，再搜索物品或按空间布局逐级下钻选择；
- 物品库使用购物车式添加：不显示勾选框，点击单件右侧“＋”加入本次待添加区；
- 页面下方持续显示“本次添加”的物品，可逐项移除，确认后一次加入目标容器；
- “添加移动容器”放在全部容器卡片之后，避免抢占物品清单的首要位置；
- 新建行程时不提供“行程中新增物品”，先用物品库已有物品完成档案；
- 档案建立后如确有需要，可使用“行程中新增物品”创建正式物品档案，同步物品库后再加入移动容器；
- 新建页不提供独立的重点关注或核对提醒入口；星标直接并入添加物品流程；
- 行程分组仅用于本次行动，不改变物品真实位置。

### 星标与批量物品管理

- 清单顶部说明当前星标提醒规则，并提供“设置－偏好设置”跳转入口；
- 容器列表上方提供“全选全部物品”和“清除选择”；
- 添加完成后，每件物品左侧保留勾选框，右侧提供星标；
- 移动端侧滑物品行后显示右侧删除按钮，拖拽物品可移动到其他移动容器；
- 物品选择、批量导入、移动和删除共用同一套批量选择能力；
- 勾选一项或多项后，底部只显示“标记、移动、删除”三项批量操作；再次点击“标记”会清除所选物品的星标；
- 删除单件或批量删除都必须二次确认；这里的删除仅代表从本次行程移出，不删除物品库档案；
- 每张容器卡片提供明确的“移除”按钮，不使用无实际操作的省略号；移除容器前二次确认，并同时移出该容器在本次行程中的物品，但不删除物品空间中的容器或物品档案；
- 所有物品仍参与完整核对，星标仅代表优先关注和提醒；
- 星标物品默认在出发时间和结束时间的前一天晚上提醒核对；
- 默认提醒时间不在单个行程中重复配置，统一放入“设置－偏好设置”，后续也可在那里关闭；
- 新建页的通用信息本轮只保留备注。

## 5. 行程档案详情

详情页首先展示：

1. 名称、类型和往返方式；
2. 完整开始/结束时间，以及单程或往返各段的地点、途经点和出行方式；
3. 按移动容器展示的物品清单；
4. 与当前行程阶段匹配的一个核对按钮；
5. 与核对按钮放在同一操作卡片、并只在核对完成后出现的物品核对状态进度；
6. 一个“通用信息”大区域，其下按类型分别显示独立的备注卡片、时间线卡片和其他自定义卡片。

核对按钮随阶段变化：

| 行程阶段 | 按钮     |
| -------- | -------- |
| 开始前   | 出发核对 |
| 进行中   | 随时核对 |
| 结束后   | 结束核对 |

开始前不显示空的“当前阶段”或准备度。完成核对后，在核对按钮上方根据本次结果显示已确认、未找到和跳过数量。

档案建立后，物品清单区保留“添加与管理物品”和“行程中新增物品”两个入口；前者统一处理添加、星标、批量移动和移出，后者创建正式物品档案并同步物品库。

详情页暂不默认展示天气、攻略、预订、预算或地图，避免误导用户认为行程就是旅行。

## 6. 旅行与其他高级扩展

扩展能力采用嵌入行程档案“通用信息”区域的自定义信息卡片，由用户主动添加。本阶段不设置单独的旅行扩展视图，也不另设“自定义信息卡片”分区标题。通用信息只是共同的大区域，各种内容仍按卡片类型分开呈现，不能塞进同一张外层卡片。

- 卡片标题和信息项可自定义，交互参考物品档案的自定义属性组；
- 备注、时间线、清单和金额统计分别使用独立卡片；卡片类型只决定内部呈现方式，不在档案页面显示“多行文本”“时间线 / 分页”等类型标签；
- 已接入“键值信息”“时间线 / 分页”“清单”“金额统计”等格式；
- 时间线 / 分页可用于每日安排、分段计划或搬家批次；
- 也可记录用户自己的旅行攻略、花销、预订或其他文本资料。

旅行攻略指用户在该旅行档案中自己编写和维护的攻略，不是外部平台攻略接入。

扩展卡片遵循以下规则：

- 不出现在新建行程的必填主流程；
- 没有填写时完全不显示；
- 可以改名、排序和删除；
- 可以新增多个卡片，并删除卡片内的信息项；
- 不影响物品清单及核对；
- 第一阶段全部本地保存，不承诺联网抓取、自动解析或第三方内容。

## 7. 物品位置规则

- 通勤、旅行和普通外出只记录携带关系，不修改物品档案位置。
- 行程分组不能创建真实容器并移动物品。
- 搬家可以在行动结束后生成“位置变更建议”。
- 只有用户确认目标空间后，才逐项或批量更新物品真实位置并写入位置历史。
- 未确认、未找到或跳过的物品不能自动更新位置。

## 8. 已接入的数据模型

数据库已升级为 IndexedDB v8；行程模块仍为 v2，内部 Plan 数据模型升级为 modelVersion 3，核心行程当前包含：

```text
Plan / activities
├── 基本信息与类型
├── 完整 startsAt / endsAt
├── 单程或往返 legs
│   └── 起点、途经点、终点、分段时间和交通方式
├── 移动容器引用与整包导入快照
├── packingItems
├── 每条 packingItem 的 starred 状态
├── notes
├── infoCards
└── checkSessions
```

`packingItems` 中的正式物品保存稳定 `itemId` 和 `containerId`；`containerRefs` 记录是否整包导入、导入时间和当次导入的物品 ID。无法安全关联容器的旧条目会保留迁移待处理标记。`checkSessions` 独立保存每次出发、途中和结束核对结果，并支持待核对、已确认、未找到和跳过。

星标提醒时间属于全局偏好，不跟随每个行程重复保存；偏好模型已经增加“出发前提醒”和“返程/结束前提醒”，默认值均为前一天晚上 21:00。当前只负责保存和展示规则，尚未接入系统通知。

## 9. 工程校正版确认结果（2026-08-07）

1. 视觉组件统一沿用物品模块 v3 的蓝灰体系，搜索、按钮、表单和卡片不再使用另一套暖色样式。
2. 单程和往返都使用完整开始/结束时间；往返另有独立返程路线，两段交通方式不强制相同。
3. 路线支持途经点；当前按去程、返程两段表达，不引入酒店、订单等酒旅业务概念。
4. “添加物品”可先保存草稿并进入二级清单，不再被完整建档校验拦截。
5. 选择已有移动容器默认带入全部后代物品，并以快照方式保持行程稳定。
6. 自定义信息卡片和月历连续周期条已经进入正式工程；周轴收敛为行程圆点，并由用户确认升级为行程模块 v3；App 发布版本不变。
7. 月历周期条使用多色和标题；时间轴左侧使用双色节点虚线，拉开与起止时间的间距。
8. 携带清单和物品库改为弹窗内连续下钻；容器选择改为目录优先、按需展开新建字段，并补齐容器移除入口。

## 10. 下一轮优化建议（尚未进入原型）

1. 高频场景优先设计“保存为常用行程 / 复制上次”，自动重复只作为后续高级选项。
2. 明确点击星标提醒后的核对范围：建议先核对星标物品，再提供“继续核对全部”。
3. 为“行程中新增物品”设计最小表单，只填名称、图片、分类和放入哪个移动容器，完整档案稍后补充。
4. 自定义信息卡片较多时默认折叠为标题和摘要，展开后再显示时间线、分页或清单。
5. 补齐无物品、未授权通知、核对中断和未找到物品的空状态与恢复路径。
